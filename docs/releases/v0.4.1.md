Who your coordinates can be shared with is now one setting, `share.audience`. This is the first release with it: 0.4.0 was tagged but its release never built, so its changes ship here.

## New

- **`share.audience`** replaces `share.enabled`, `share.candidates` and `share.require-mayor`. It's one of `off` (the default), `mayor`, `mayor-world-group`, `world`, `world-group` or `server`. The README says what each one does.
- An unknown value turns sharing off, with a console warning. That warning now also shows after `/bluemapmini reload`, not only at startup, so a fix made with a reload is confirmed straight away.

## Fixed

- A bare `audience: off` was read as a typo. YAML reads a bare `off` as false, so the plugin warned at every start. It still meant off, so sharing was never on by mistake. The shipped config now quotes it, and an unquoted `off` is read correctly too.

## Upgrading

Replace the jar. An older config keeps its old sharing: the old keys are read once and mapped to the narrowest audience that matches, so an upgrade never widens who can receive a share. The old defaults become `mayor-world-group`, and `enabled: true` with `candidates: all-online` becomes `mayor`. You can then write `audience:` yourself and remove the old keys.

## Tested

- 70 unit tests pass, including the migration from the old keys, a bare and a quoted `off`, and `on` failing closed.
- The live suite passed on Paper 26.3 with BlueMap 5.29 and a protocol bot: 334 of 335, with the client font check skipped (it needs a Minecraft client classpath). The share checks cover `world-group` leaving out a player in another world, `server` reaching them, `off`, an unknown value failing closed with its warning, and `mayor` staying off without Mayor.
- The real Mayor 0.7.0 test passed 8 of 8: shares reach only the sender's circle, a player with no circle in a circle-only world sends nothing, and without Mayor `mayor` stays off with a console line saying why.
- Not run on 26.1.2 or 26.2 for this release. Not seen in a real game client.
